# Trusted by rule: a standing Reference review the researcher declares in advance

**Status**: accepted (decided in #129, #130, #131; specified in #134). Amends ADR-0004 (a second way an Imported result gains standing, still only by the researcher's decision) and ADR-0012 point 5 (conditional auto-trust, deferred there, is decided here).

## Context

Every Imported result needed its own Reference review, even the tenth citation of the same textbook. ADR-0012 deferred a rule that treats a reference meeting certain conditions as trusted. Any such rule has to survive two constraints: ADR-0004/0010 — only the researcher's recorded decision gives a node standing, and a decision not in a commit by the reviewer's identity has no record — and the fact that every field a rule could read (the citation's `source_type`, `identifier`, the node's `TrustLevel`) is written by whoever imported it, agents included.

## Decision

1. **A Trust rule is a Human Review decision made in advance.** It is declared, amended and retired only by the researcher, on the proof map page, and recorded like every other decision: one line in the git-tracked `proofs/trust-rules.jsonl` (the first project-level decision file; the same line shape as a node's `reviews.jsonl`, kind `trust_rule`, decision `declare` / `amend` / `retire`, the rule's name as `target_id`, its conditions in the payload), committed as the reviewer's git identity with the message `trust rule <name>: <decision>`. A rule has an immutable name, a required rationale and one or more conditions (`TRUST_RULE_EMPTY` otherwise); the rule set in force is the file folded from the start, and a retired name is never reused (`TRUST_RULE_NAME_TAKEN`). No CLI command and no agent declares or changes one; `proof trust-rule list` and `show` only read them.
2. **Trusted by rule is derived, never written.** A node that meets a rule gets no decision line. Its acceptance state reads `trusted-by-rule` and dependents treat it as Reference-reviewed. Precedence: `no-longer-callable` (final) > a counting explicit Reference review > `trusted-by-rule` > `unverifiable` > `unreviewed`. An explicit decision on the node always wins; resolving a Challenge is always explicit. The first time a node meets a rule is noted as an event in the project's event log (never a decision), so the node's history says since when, and under which rule, it was callable.
3. **Conditions are ranked by who can fabricate them.** Agent-proof: `source already reviewed` — the same `reference_id` at the same `source_version` carries a counting explicit Reference review on another node of this project; never transitive, and poisoned when any citation of that source at that version becomes no-longer-callable. Typed metadata, accepted under ADR-0010's cooperative-agent scope: `source_type in {…}`, `identifier has DOI`, `identifier has arXiv` (recognised by pattern, never checked online). Never: the node's own `TrustLevel`, free-text fields, library folders. Conditions within a rule conjoin; rules disjoin. The vocabulary is a closed enumeration, not an expression language; a rule that trusts `website` or `other` sources is allowed, with a reminder on the page. A node with no `reference_id` meets nothing, and conditions read the citation's fields as they are now.
4. **Losing a rule is losing standing, nothing more.** Tightening or retiring a rule drops matching nodes to `unreviewed` at once; unaccepted dependents block, accepted dependents keep their Acceptance, exactly as when an explicit Reference review turns unverifiable. The page previews the impact (how many nodes lose trusted-by-rule, how many of those an Accepted node rests on) before recording the change; the preview binds nothing.
5. **The researcher sees what they haven't looked at.** The review page lists rule-trusted nodes in their own collapsed section, each with the rules it meets and a button to review it explicitly (the ordinary Reference review, its rationale prefilled `matched trust rule <name>; reviewed explicitly`); they never count as awaiting a decision. The rules themselves are managed from a sheet opened there, not on a page of their own. Exchange bundles carry no rules in either direction.

## Consequences

- There is still one trust model with one author. Nothing an agent writes can, by itself, make an Imported result callable; the most it can do is satisfy a rule the researcher declared and can see the effect of.
- `_dependency_satisfied` counts `trusted-by-rule` as standing; `acceptance_state` gains that value for Imported results only (the CLI's `--json` reads an imported result's Reference review state on that axis, as the page always has); `--json` carries `trust_rule` with every matching rule's name.
- Whether an Accepted dependent should read potentially-stale when any dependency loses standing is a separate question about ADR-0004's derivation, not decided here.
- Reversing this means removing a derived value and a decision file; no node record was written, so nothing has to be unwritten.
