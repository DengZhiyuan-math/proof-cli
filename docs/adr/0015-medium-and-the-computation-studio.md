# A node's proof may be a computation: the Medium of a node

**Status**: accepted (decided in #141, #142, #143; landed with PR #146, part 1 of spec #145; Run, Open in VS Code and frozen outputs with PR #147, part 2). Amends ADR-0010 point 1 (a node's proof is a standalone LaTeX document) and ADR-0011 (a local node's computation lives in `scratch/`, never frozen).

## Context

Some nodes are established by a computation — a case-by-case check, an enumeration, a formal verification, a simulation — not by a written argument. proof-cli gave every local node a `proof.tex`, so such work had nowhere to live and no way to be reviewed: ADR-0011 let an agent keep scripts and their output in `scratch/`, which a Review snapshot never freezes. The researcher asked that these nodes stay ordinary nodes of the map.

## Decision

1. **Medium is a node attribute, not a kind.** `medium: latex | computation` on a Theorem, Lemma or Claim (default `latex`; a node recorded before the field reads `latex`). An Imported result has none: every write path refuses one on it (`MEDIUM_NOT_APPLICABLE`) — `node create`, `node medium set` and exchange import alike. It says what the Candidate proof is made of. The state machine, Acceptance and the Accepted mathematical interface do not depend on it, and it may be changed at any time (`node medium set`): files stay, the missing entry is scaffolded, an Acceptance stands.
2. **A computation node's proof is its program.** `run.sh` is the entry, `out/` holds what it writes. The researcher's Acceptance judges whether what was frozen establishes the statement, as it always did.
3. **A computation's Review snapshot freezes its inputs, its outputs and its summary, and tells them apart** (the researcher's rule, 2026-10-02). Its *inputs* are its scripts and its data, each script with its executable bit, and the hidden environment files at the node root named by an allowlist (Q39: exactly `.python-version`, `.tool-versions`, `.nvmrc`, `.node-version`, `.ruby-version`; one constant, `vault.HIDDEN_INPUTS`, added to only explicitly). Its *outputs* are `out/`. Its key-ideas summary is frozen for the researcher's review but is no input of the program (Q40).
   - **A script writes its outputs into `out/` and nowhere else.** Anything it writes elsewhere in the folder changes its own inputs, so a later Run no longer matches the frozen program and is not recorded as Evidence (#147). The `run.sh` skeleton says so.
   - **Never frozen, for either medium:** every other dotfile and every hidden folder at any depth (`.git`, `.venv`, `.cache`, …), `scratch/`, `build/`, `__pycache__` and `*.pyc` anywhere. A computation does not freeze the shared `../preamble.tex`: its program doesn't read it, so a preamble edit is no new program version. Requesting review lists the hidden paths it left out, by path only and never their contents (the `SNAPSHOT_SKIPPED_HIDDEN` notice).
   - **Secrets are never frozen or exported, under any circumstances:** `.env`, `.env.*`, `.envrc` and `.netrc`, wherever they are. This is a hard check of its own (`vault.is_secret_path`), apart from the allowlist, so that no addition to the allowlist can let one in.
   - **What can't be read whole is refused, and nothing is written:** a file or folder that can't be read (`WORKING_FILE_UNREADABLE`), or a symbolic link where a file would be read (`NODE_FOLDER_SYMLINK`, listing each link, dangling ones too). A snapshot and an export follow no link: a link could point anywhere, secrets included.
   - The manifest (format 2) records which frozen files are executable, and the snapshot's hash covers it. A snapshot with none (every LaTeX one, every format-1 one) is hashed exactly as before, so existing snapshots still verify. Verification accepts only formats 1 and 2, and checks that each file the manifest records as executable still is.
   - `vault.frozen_role(path)` says what a frozen path is: `"input"`, `"output"` (under `out/`) or `"summary"` (`key-ideas.md`). `frozen_inputs_digest(snapshot)` and `working_inputs_digest(root, node, medium)` hash the inputs alone, so neither a new output nor a summary edit changes them.
   - **Exchange carries what a snapshot would freeze, and never a secret.** An export walks a node folder with the snapshot's own walk and filters, including inside the snapshots it carries. A snapshot frozen before this rule may hold files an export now leaves out (a `.env`, an unknown dotfile, a `__pycache__`). The export then withholds them (`withheld_files`, by path only) and says so per snapshot (the `SNAPSHOT_EXPORTED_UNVERIFIABLE` notice). The importer reads that snapshot as unverifiable, as it reads a lost one: nothing can be decided on it there until it is reviewed afresh. A snapshot missing files the export did not declare withheld is still refused (`VAULT_FILE_MISSING`).
4. **A large `out/` is a notice, never a refusal.** Requesting review returns `SNAPSHOT_LARGE_OUTPUT` (registered in `errors.NOTICE_CODES`, under `data.notices`) when the snapshot froze more of `out/` than `proof.toml`'s `[snapshot] large_output_mb` (default 50): big data is the researcher's `.gitignore`.
5. **Each run is an Evidence check, never a decision** (#147). The studio's Run runs `./run.sh`; exit 0 reads `passed`, otherwise `failed`, a run that could not start `error`; `inconclusive` is a human's or an agent's to record. Runs may be concurrent.
   - *The Evidence rule (the researcher's, 2026-10-02).* A run counts as an Evidence check on the node's current Review snapshot only when all three hold: (1) its inputs (point 3: `frozen_role` is `input`) are the ones the snapshot froze, `working_inputs_digest` before the run equal to `frozen_inputs_digest`; (2) they stay untouched for the whole run: the digest and a stamp of each input (size, mtime, ctime, inode) are compared before and after it, so an input changed and put back during the run is still seen, and an input that can't be read, or a symbolic link among the inputs, records nothing (a link under `out/` is an output, and outputs may differ; a snapshot still refuses every link, point 3); (3) the run completes: a stopped or timed-out run records nothing. Outputs may differ from the frozen ones. The check is recorded bound to the SHA-256 of the snapshot its inputs matched, read together with the frozen inputs it was compared with, as a decision is bound to the snapshot it decides on. (A check recorded by hand, `proof node evidence record`, is bound to `--snapshot-sha256` when given — refused unless it is the snapshot's hash now — and otherwise to the snapshot's hash at the moment of recording.) The node page and `node show --json` show each check's own bound hash and flag one whose snapshot has changed since. A run whose inputs differ still runs; it records nothing, and its result and output say so ("inputs differ from snapshot vN — not recorded").
   - *What such a check establishes.* The execution outcome of the frozen inputs: that this program, as frozen, exits 0 (or does not) on this machine. It does **not** certify the frozen outputs in `out/`: a rerun may write different ones, and whether those the snapshot froze establish the statement stays the researcher's Acceptance judgment.
   - *The program runs as the researcher.* `run.sh` is started as the user running the map's server, with that user's full environment, and can read and write anywhere that user can: the cooperative model of ADR-0010, not a sandbox. Its output is kept for the page up to its last 8 MB, under a note of how much was dropped, and arrives when the run ends, not streamed.
6. **Open in VS Code, and frozen outputs on the page** (#147). A computation node's bar offers Run and Open in VS Code: `vscode://file/<folder>` (percent-encoded), which the page opens itself, or a configured `[studio] open_command` (`{folder}`, `{file}`), which the server runs. The node page lists a snapshot's `out/` artefacts with image previews, each served as a download or a sandboxed raster image, never as active content.

## Consequences

- `node create --medium`, `node medium set`, `--medium` on `fog crystallize`; `medium` in every node view and `--json`, and in exchange bundles (which carry a computation's allowlisted environment files and executable bits, never a secret); the sample fixture gains a computation claim.
- The key-ideas summary keeps its four headings and its requirement (#103) for both media; its skeleton for a computation hints at what each holds. Request review, snapshots and every Review decision work as before.
- ADR-0011's "scripts and their output in `scratch/`" remains true of a LaTeX node's working computation; a computation node's program is its candidate proof and is frozen.
- Reversing this means removing one field; nothing in the trust model would have to be undone.
