# Four packages: the core, the proving framework, the LaTeX studio and the web app

**Status**: accepted. Amends ADR-0011 point 3 (where the studio's code lives and what it may import) and ADR-0017 (where the Home lives). Nothing a researcher or an agent does changes: `proof` is the same CLI, `proof home` and `proof map open` the same commands, the page the same page.

## Context

By ADR-0017 one package, `proof_cli`, held three different things: the proof map and its project state with the agents' command surface (the core); the proof map web app — the Home, a project's page, a node's page — that the researcher works in; and, under `studio/`, prism-local's LaTeX studio with the Proof agent's roles and its run grafted onto it. The web app imported the core, the studio imported the core (`key_ideas.KEY_IDEAS_FILE`, `vault.RUN_SCRIPT`, `domain.AGENT_ROLES`) and the run, the core's CLI imported the web app for three commands, and the `proof` wheel shipped CodeMirror, PDF.js and KaTeX to every agent that only ever runs `proof node …`. A fix to the page meant a release of the CLI; the studio could not be taken from prism-local, or given back, without touching the core; and the proving framework — which roles there are, how a run moves between them, when it stops — had no place of its own to be designed in.

## Decision

1. **Four packages.** The core stays at the root of this repository. latex-agent lives beside it under `packages/latex-agent/`, with its own `pyproject.toml`, `src/` and `tests/`: it is prism-local's code, taken by hand (ADR-0011 point 3), and stays where that taking happens. proof-agents and proof-web are repositories of their own, private, in the zeqome organisation (`github.com/zeqome/proof-agents`, `github.com/zeqome/proof-web`); each began as `packages/<name>` here at commit `4d4461b`, and proof-web carries copies of the core's test helpers (`_proofs`, `_researcher`, `fixtures/`) so its tests run alone.

   | package | import name | what it is |
   |---|---|---|
   | `mathematical-proof-cli` (root) | `proof_cli` | the base: project state, the proof map, Human Review authority, the `proof` CLI — the agents' interface (ADR-0006) |
   | `proof-agents` | `proof_agents` | the automated proving framework: the Proof agent's roles — brief, permissions, write scope (`proof_agent`) — and the run that works a node as those roles in turn, a state machine the researcher starts, pauses, redirects and releases (`agent_run`) |
   | `latex-ai-agent` | `latex_agent` | the LaTeX studio taken from prism-local (ADR-0011 point 3): editor, build, PDF with SyncTeX, the agent panel and its Claude Code and Codex backends, the compile tool. Standard library only; a TeX distribution or Tectonic to compile |
   | `proof-web` | `proof_web` | the web app: the Home (ADR-0017), each project's proof map page and node pages (ADR-0008, ADR-0010), one studio per node served inside the page (ADR-0011), and the CLI's `home`, `map open` and `map serve` |

2. **Dependencies point one way.** `proof_web` imports `proof_cli`, `proof_agents` and `latex_agent`. `proof_agents` imports `proof_cli` (its domain: the roles). `latex_agent` imports nothing of the repository: what it used to take from the core it is now given — the studio is constructed with the names of the folder's summary file and program (`key_ideas_file`, `run_script`; standalone, the defaults are the same names) and with a factory for its run (`run=lambda agent: AgentRun(agent, hooks)`), whose interface it only calls (`start`, `pause`, `resume`, `redirect`, `release`, `review_now`, `view`, `work_log`, `turn_list`, `active`). The framework, in turn, runs its turns on whatever agent manager it is handed (`latex_agent.agent.AgentManager`: `start`, `stop`, `jobs`), and a backend reads the turn's `ProofAgentContext` through the job without importing it. `proof_cli` imports none of the three.

3. **The core's CLI takes commands from plugins.** `proof_cli.plugins` loads every `register(app, map_app, review_app)` published under the entry-point group `proof_cli.commands`; proof-web's adds `home`, `map open`, `map serve` and the hidden `review serve` / `review open`. Where a project's page is — its origin, one port per project instance — is the project's own matter and stays in the core (`proof_cli.origins`), so a refused Human Review decision says the URL whether or not proof-web is installed; proof-web imports the derivation from there. Without proof-web the three commands exist as fallbacks that answer `WEB_APP_NOT_INSTALLED` and name the package, so `proof map open` is never "no such command", and the agent skill's commands all resolve. `python -m proof_web.cli …` is the same CLI with the commands whether or not the entry point is installed (the Home and `map open` start their background processes through it), given proof-cli, proof-agents and latex-agent importable.

4. **Tests follow their code.** The core's tests stay in `tests/`; the state machine's own tests (a fake agent, hooks that assign and release) are proof-agents'; prism-local's tests and the wheel's packaging test are latex-agent's; everything that drives a page, a studio in a node, or a run through the hub is proof-web's, with its own copies of the core's test helpers. The few core tests that look at the page do so only when proof-web is importable (`pytest.importorskip`). One `pytest` at this root runs the core's and latex-agent's trees; the other two run in their repositories.

## Consequences

- A researcher installs the core and proof-web (which brings the other two); an agent's machine needs only the core, and the `proof` wheel no longer carries a browser's worth of vendored JavaScript.
- Taking prism-local's changes (ADR-0011 point 3, as updated) now lands in `packages/latex-agent/`, and nothing in it names the proof map; what a node's studio needs from the map arrives through its constructor. Designing the proving framework — more roles, another hand-off rule, another stop condition — happens in proof-agents against one interface (`RunHooks`, the agent manager) with tests that need no CLI, no studio and no browser.
- **Left for a next step:** the studio page's node panel (`node.js`), run pane (`run.js`) and maths renderer (`mathtext.js`) are proof-cli's additions and speak to proof-web's routes, yet still ship in latex-agent's `static/` because the page is one HTML file. Moving them to proof-web means assembling the node page there. Until then latex-agent is clean in Python and proof-map-aware in its page. The proof map page also loads KaTeX and `mathtext.js` from latex-agent's static folder (`/static/shared/`), as before.
- The project list (`projects.json`, ADR-0017) now has writers in several processes — the Home, `proof init` and `proof map open` in terminals, an agent's `proof init` — so each change is one transaction under a cross-process lock (`projects.json.lock`); two registrations at once used to lose one.
- **A page belongs to a project instance, not a folder** (found in review). A folder can come to hold another project — deleted and started again at the same path, from the Home or a terminal — while a page, its studios and an old agent turn still exist. So `ReviewApp` and `StudioHub` remember the instance id (and project id) they were made for and check it before acting: a page whose project is gone answers 410 `PROJECT_REPLACED` to everything but its health (answered from what it was made with, reading nothing) and its files; a stale hub refuses Start and Review-now and makes no studio; the run's hooks that land after a turn — a release, a stuck step, a draft, a run's record — write nothing. The Home's `ProjectHub` keys its pages by instance too, retires a stale page (detached first) on open, forget, create and close, and closes every page even when one fails to.
- Error codes stay one registry (`proof_cli.errors`): `WEB_APP_NOT_INSTALLED` joins it. The `proof_cli.commands` entry point is the only extension seam; there is no plugin API beyond it.
- ADR-0017's paths (`webapp/home.py`, `src/proof_cli/studio/README.md`) now read proof-web's `src/proof_web/home.py` and `packages/latex-agent/src/latex_agent/README.md`.
